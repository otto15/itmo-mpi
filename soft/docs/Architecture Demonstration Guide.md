# Демонстрация архитектурно значимых сценариев Drakkar ERP

Этот файл — готовый маршрут живой демонстрации Soft. Он показывает несколько походов и ролей, работу флота и склада, завершённые походы, а также разделение данных поселений.

## Подготовка

```bash
cd soft
cp .env.example .env
docker compose up --build
```

Перед первым запуском заменить `DB_PASSWORD` и `PROVISIONING_KEY` в `.env`.

Открыть `http://localhost:8088`, войти как `ragnar` и на экране «Обзор» нажать «Восстановить исходные данные».

## Что уже находится в демо

В Каттегате шесть походов:

- Уэссекс — в плавании, два готовых корабля на 60 мест;
- Оркнейские острова — второй поход, одновременно находящийся в плавании;
- Нортумбрия — в подготовке, требуется 70 мест, готово 20, с учётом строящегося корабля запланировано 60;
- Шетландские острова — полностью готовый к запуску поход с кораблём и подтверждённым участником;
- Фризия и остров Мэн — завершённые походы с добычей и историей действий разных ролей.

В Бирке находится отдельный поход к Готланду, собственный корабль и другой склад. Пользователь не выбирает и не переключает поселение: оно определяется сервером при входе.

## Подробный сценарий

### 1. Список походов и флот

1. Войти как `ragnar`.
2. Открыть «Походы».
3. В списке одновременно видны Уэссекс и Оркнейские острова со статусом «В плавании».
4. Выбрать Уэссекс. В карточке отображаются «Морской змей» и «Волчий клык»: 40 + 20 = 60 готовых мест при потребности 55.
5. Выбрать Нортумбрию. В карточке отображаются готовый «Ворон» и строящийся «Северный ветер».

Здесь видно, что поход не хранит одно текстовое имя корабля. Флот образован отдельными связями, а вместимость рассчитывается по типам назначенных кораблей.

### 2. Управление флотом и запуск

1. Выбрать поход к Шетландским островам. В блоке готовности три зелёных условия: вместимость набрана, корабли готовы, команда подтвердила участие.
2. Нажать `×` у «Ледяной чайки». Вместимость станет нулевой, кнопка «Начать поход» заблокируется, а корабль появится среди свободных.
3. Добавить «Ледяную чайку» обратно.
4. Нажать «Начать поход». Статус изменится на «В плавании», а в истории карточки появится событие запуска.

Backend повторно проверяет все условия внутри транзакции. Нельзя запустить поход с недостроенным кораблём, нехваткой мест, без подтверждённых участников или пока кто-то не ответил.

### 3. Запрос нового корабля

1. В карточке Нортумбрии обратить внимание: требуется 70 мест, запланировано 60.
2. В блоке «Запросить строительство» выбрать «Кнорр».
3. Показать рецепт до отправки: дерево, ткань и смола берутся из справочника типа.
4. Ввести имя, например «Скат», и нажать «Передать заказ на верфь».
5. Убедиться, что новый корабль появился во флоте похода со статусом «Строится», а плановая вместимость выросла до 80.

Сервер одной транзакцией создаёт корабль, заказ, связь с походом, снимок рецепта по этапам и событие в карточке похода.

### 4. Склад и верфь

1. Открыть «Ресурсы»: слева показаны реальные остатки поселения, справа — полные рецепты кнорра и драккара.
2. Выйти и войти как `floki`.
3. Открыть «Походы»: кораблестроитель видит Нортумбрию, потому что с ней связан его заказ.
4. Открыть «Верфь». В списке есть «Северный ветер» и созданный заказ; в карточке указано, для какого похода строится корабль.
5. Для «Северного ветра» завершить два этапа. Остатки дерева и смолы уменьшатся.
6. Попытаться завершить последний этап без Блота: сервер вернёт `BLESSING_REQUIRED`.
7. Войти как `godi`, открыть «Верфь» и подтвердить Блот.
8. Вернуться под `floki` и завершить корабль.

Списание ресурсов, переход этапа и событие выполняются одной транзакцией. Тест дефицита отдельно подтверждает, что при ошибке не меняется ни склад, ни этап.

### 5. Команда и конкурентное изменение

1. Войти как `ragnar`, открыть «Команда».
2. Добавить свободного жителя в Нортумбрию.
3. Войти как `halvdan` и подтвердить своё ожидающее назначение.

API проверяет принадлежность назначения текущему воину и ожидаемую версию. Интеграционный тест дважды отправляет ответ с одной версией: первый сохраняется, второй получает `STALE_CREW_ASSIGNMENT`.

### 6. Итоги и история походов

1. Войти как `ragnar`, открыть «Итоги» и выбрать нужный поход в плавании.
2. Указать добычу и при необходимости отметить потери.
3. Нажать «Рассчитать Вергельд», затем «Утвердить итоги».
4. Открыть «Историю».
5. Выбирать завершённые походы в компактном списке. В карточке видны добыча, использованный флот и связанные события ярла, воина, кораблестроителя или жреца.

Фиксация итогов одной транзакцией сохраняет добычу, потери, Вергельд, пополнение склада, статус и аудит. После фиксации изменение запрещают и application service, и trigger PostgreSQL.

### 7. Изоляция поселений

1. Запомнить походы и остатки Каттегата.
2. Выйти и войти как `erik` / `birka-2026`.
3. В шапке автоматически указана «Бирка».
4. В «Походах» доступен только поход к Готланду.
5. В «Ресурсах» показаны остатки Бирки; списка и переключателя поселений нет.

Клиент не передаёт `settlement_id`. Сервер получает его из проверенной сессии и добавляет во все бизнес-запросы. Интеграционный тест дополнительно обращается с сессией другого поселения к UUID Каттегата и получает `404`.

## Покрытые архитектурные механизмы

| Механизм | Демонстрация | Автоматическая проверка |
|---|---|---|
| Ролевая авторизация | разные данные и действия ярла, воина, кораблестроителя и жреца | HTTP-представления ролей и отзыв сессии |
| Изоляция поселений | `ragnar` видит Каттегат, `erik` — Бирку | `seededBirkaAccountSeesOnlyItsOwnExpeditionAndWarehouse` |
| Флот из нескольких кораблей | два корабля Уэссекса | `expeditionFleetContainsSeveralShipsAndCapacityIsDerivedFromTheirTypes` |
| Управление флотом | снятие и возврат корабля в подготовке | `jarlRemovesShipFromPreparationFleetAndDetachesItsBuildOrder` |
| Запуск похода | готовность Шетландов и блокировка Нортумбрии | `readyExpeditionStartsButIncompleteFleetIsRejected` |
| Заказ и рецепт | запрос кнорра из карточки Нортумбрии | `jarlRequestsShipFromCatalogAndRecipeIsSnapshottedForTheExpedition` |
| Связь похода с верфью | поход отображается у кораблестроителя | `shipbuilderSeesTheExpeditionBehindTheConstructionOrder` |
| Конкурентное изменение | личный ответ воина | `staleParticipationDecisionIsRejected` |
| ACID склада и верфи | завершение этапа | `insufficientStockRollsBackBothStockAndStage` |
| Серверный запрет без Блота | последний этап | `finalShipStageRequiresPriestBlessing` |
| Неизменяемые итоги | утверждение Вергельда | `finalizationCommitsLedgerAndDatabaseMakesResultsImmutable` |
| Аудит в контексте похода | события внутри карточки | проверки записи событий в бизнес-тестах |

## Автоматическая проверка

```bash
cd soft/backend
mvn test
```

Текущая версия содержит 21 тест: 18 интеграционных и 3 модульных. Ожидаемый результат: `Failures: 0, Errors: 0`.

Frontend:

```bash
cd soft/frontend
npm ci
npm run build
```

Схема таблиц и команды для её просмотра находятся в [Database Schema.md](Database%20Schema.md). ## Повтор демонстрации

Войти как `ragnar`, открыть «Обзор» и нажать «Восстановить исходные данные». Сброс изменяет только демонстрационный Каттегат; Бирка остаётся отдельным поселением.
